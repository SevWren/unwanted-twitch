### Coding Style Restrictions
To maintain consistency with the existing codebase, adhere to these restrictions:

#### JavaScript Syntax and Structure
- **ES6 Only**: Use ES6 features (e.g., `const`, `let`, arrow functions) with `// jshint esversion: 6` at file start.
- **Naming Conventions**:
  - Variables: camelCase (e.g., `blacklistedItems`).
  - Constants: UPPER_CASE (e.g., `storageSyncMaxKeys`).
  - Functions: camelCase with descriptive verbs (e.g., `getDirectoryItems`).
- **Comments**: Use `/* BEGIN: section */` and `/* END: section */` for logical blocks, JSDoc for functions.
- **Semicolons**: Always include semicolons at statement ends (e.g., `let x = 1;`).

#### Error Handling and Logging
- **Logging**: Use custom functions from `common.js`:
  - `logTrace`, `logVerbose`, `logInfo`, `logWarn`, `logError` based on `debug` level (0-5).

- **Error Handling**: Always use `try/catch` for async operations, log with `logError`.

#### DOM Manipulation
- **Selectors**: Use specific class-based selectors (e.g., `.Layout-sc-1xcs6mc-0.jCGmCy`).
- **Hiding**: Prefer `classList.add('uttv-hidden-item')` over `style.display = 'none'` unless unavoidable (e.g., sidebar in `directory.js`).
- **Event Listeners**: Attach directly to elements, avoid delegation unless performance-critical.

#### Storage and Async Operations
- **Storage**: Use `storageGet`, `storageSet` wrappers from `common.js` for mode-agnostic access.
- **Async**: All Chrome API calls must be `async/await`, no callbacks (e.g., `await chrome.tabs.create({...})`).

#### Modularity and Scope
- **File Structure**: One file per major feature, no inline scripts in HTML.
- **Global Scope**: Minimize globals, use runtime variables within files (e.g., `let initRun = false` in `directory.js`).

#### Performance
